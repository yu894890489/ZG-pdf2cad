# 铁塔图纸 → 三维模型:全流程、关键点与踩坑记录

> 项目:SZK31102A(220kV 双回路钢管塔,126 张图纸)
> 目标:PDF 图纸 → 三维杆系模型(SCAD/JSON)+ BOM + 碰撞检查 + 64 呼高/接腿变体
> 截至 2026-09-30:基准塔 566 杆 / 粗略级 93.27t,64 变体全套输出。

---

## 一、总流程(最终有效的管线)

```
PDF 图纸 (126张)
  │  ① 转 DXF + 建目录
  ▼
demo/dxf_converted/*.dxf ──► demo/catalog_db.json (126张:图号/比例/类别)
  │  ② OCR(文字全被炸成轮廓,无 TEXT)
  ▼
尺寸表/根开表/重量表/单线图标注 (rapidocr 200dpi 分块)
  │  ③ 选定权威视图:001 正视图
  ▼
DXF 黑线矢量提取(过滤标注层)→ 轴线段 → 节点图
  │  ④ 参数化重建
  ▼
demo/rebuild_tower.py ──► demo/frame.json (566杆) + tower_frame.scad
  │  ⑤ 规格挂接(BOM)
  ▼
demo/attach_specs.py ──► frame.json 带 spec/重量 + demo/bom.csv
  │  ⑥ 碰撞检查
  ▼
demo/collision_check.py ──► demo/collision_report.txt
  │  ⑦ 变体批量生成
  ▼
demo/variants.py ──► demo/variants/ (64套 json+scad) + variants_summary.csv
```

各阶段产物与脚本:

| 阶段 | 脚本/产物 | 说明 |
|---|---|---|
| PDF→DXF | `demo/dwg2dxf.py`, `demo/scan_all_dxf.py` → `catalog_db.json` | 126 张全部转 DXF 建目录 |
| OCR | `demo/ocr_sheet_tiled.py` | 200dpi 分块 OCR;小表格(根开表/重量表)需 300dpi 局部裁剪 |
| 轴线提取 | `demo/leaf_pipeline.py`(通用模板)、`demo/extract_001_full.py` | DXF 过滤 + 共线聚类 + 节点图 |
| 重建 | `demo/rebuild_tower.py` | 唯一的"权威"建模脚本,全部坐标来自 001 提取 |
| 规格 | `demo/attach_specs.py` | 按 mid/role 前缀路由规格,算重量 |

## 二、各阶段关键点与思路

### ① 图纸目录与层级

- 先把 126 张全转 DXF,逐张扫图框建 `catalog_db.json`,再手工整理层级关系(`docs/drawing_hierarchy.md`)。
- **思路:建模前先"看地图"**——知道哪张是正视图、哪张是细部、哪张是 BOM 表,后面每一步找数据才有方向,避免随机翻图。

### ② OCR:图纸文字全是轮廓

- 图纸文字被炸成矢量轮廓,DXF 里**没有 TEXT 实体**,只能 OCR。
- rapidocr 200dpi 整页分块够用;**小字表格(根开表 64 格、002 重量表)必须 300dpi 单独裁剪重跑**,整页跑会漏/错。
- pypdfium2 渲染 `scale=8`(~2.3GB 内存)OK;`scale=12` 出空白页,不要超。

### ③ 权威视图的选择:001 正视图是唯一权威

这是整个项目**最重要的架构决策**:

- 单线图(004)、平面图(008)、腿部详图全部有比例/压缩问题,只当**辅助证据**,不当坐标来源。
- x/z 坐标一律以 001 正视图提取值为准;其他图纸只用来确认"拓扑形状"(哪里有腹杆、哪根是弦杆)。
- 001 DXF 坐标→模型 mm 的映射:`model = ((x−220.2)×105.33, (y−17.1)×105.33)`。

**DXF 实体过滤(反复踩坑后定下的规则):**
- 几何:layer `PDF_几何图形`,entity color 256(bylayer)或 7(黑)
- 排除:4=青色尺寸标注、6=品红符号/编号、2=黄色中心线、1=红色文字注记
- 不做这个过滤,标注线会混进几何,提取结果面目全非

**提取算法**(leaf_pipeline.py):
1. 按层/色过滤 → 直线段集合(LWPOLYLINE + LINE)
2. 共线聚类合并断线(perp tol 60)——**会过度合并**,只能做初筛
3. 精确重建靠**端点吸附节点图**(snap tol 120):端点相近的线连成节点,从节点图读拓扑
4. 局部区域(如 L1 挂线头)单独重提取 + 手工核节点链,别信一次性全局提取

### ④ 重建(rebuild_tower.py)的建模约定

- **塔身**:直线锥腿 (±13953,0)→(±2904,92364),再分两段收口至 (±1637,133860);4 根角柱独立建。
- **腹杆三段式**:底部人字撑(0~19355)→ 中部菱形(19355~92364)→ 上部 X 撑(92364~133860);横隔按图纸有水平材的标高建。
- **横担**统一走 `build_crossarm()`(上弦折线点 + 下弦折线点 + 自动 W 腹杆 + 次腹杆 + 横隔,y 半宽从根到梢线性收窄):
  - L1 地线支架 = **W 形上弦**(塔顶缓降→谷点 ±11405→上翘挂线峰 ±16021/134955,高出塔顶 1.1m)+ **W 挂线头**(头内折线腹杆 + 尾杆 ±17140)
  - L2/L3 = 芬克式悬臂桁架(下弦水平 + 上弦斜 + W 腹杆)
- 杆件统一 `add(role, p1, p2, r, kind, tag)`,role/mid 前缀同时决定颜色、规格路由,一套约定贯穿 json→scad→BOM→碰撞。
- **镜像一定要 ±sx 和 ±sy 双层循环**——第一版 W 头漏了 ±sy,正面看着对、俯视图缺一半。

### ⑤ 规格挂接(粗略级 BOM)

- 文字全靠 OCR 抠:腿部主材 φ660×14 Q420(实测)、上段主材 L125×8(013)、各横担弦腹杆(004/005/007/008);中段 φ550×12 是插值估的。
- 挂接逻辑:mid 前缀(L1/L2/L3/LEG/BR/XB/DIA/VG)+ role 里的"弦/次腹"关键词 → 规格。
- 重量按型钢线密度 × 杆长累加。**模型 93t vs 002 表 135m 塔约 385t**:差 3 倍多属预期——粗略级没有节点板/法兰/爬梯/脚钉,meta 里已注明,别当成 bug 修。
- 002 重量表 16×4 实测值嵌在 variants.py 的 `W002` 字典里,用于变体对照。

### ⑥ 碰撞检查的判据设计

胶囊体两两测距,分类而不是只报"撞了":

- 端点距离 <1mm = **共节点,跳过**(是连接不是碰撞)
- 端点落在对方轴线上 = **T/Y 节点连接**(腹杆接到弦杆上,设计如此)
- 同面 XB 对在段中交叉 = **X 撑设计交叉**
- 其余 min_dist < r1+r2+10 才算碰撞;再留一档"接近"(<+100)人工看

**当前 96 对"碰撞"全部是腹杆端点离弦杆轴线 1~2mm 的节点区假阳性**(胶囊判据对"端点擦到杆身"不敏感)。这类数字要配明细读,别只看总数归零——判据放宽到 0 碰撞通常等于把真碰撞也放走了。

### ⑦ 变体生成(64 套)

- 维度:呼高 H∈{90..135, 步 3} × 等长接腿 L∈{0, 1.5, 3, 4.5}。
- **呼高 H = 呼称高 = 挂点高**;塔全高 = H×1000 + 34708。
- 本体 = 图面塔(99.0m 呼高档)沿 z 截剪平移,使挂点恒落在 H×1000;H>99 时按根开表坡度合成下延段。
- 接腿区只有横隔没有大叉(001 图面证实),别想当然加斜材。
- 每套输出 json + scad + 汇总 CSV,重量同时给模型值和 002 表值对照。

## 三、踩坑清单(按杀伤力排序)

1. **根开表表头是"半根开"**:表值 ×2 才是全根开;青色标注 37560/36840 就是 135/132 呼高的真全根开。早期结论"37560 是尺寸框线"是错的,靠 64 格 OCR 逐格拟合出规律 `半根开 = 18780 − 120×(135−H+L)` 才翻案。
2. **0.745 压缩因子出现了三次,都是同一个坑**:
   - 001 正视图底部 ±13988 的"足点"是 8 个变体接腿的压缩示意,≠真根开;
   - 004 单线图标注 1:100 实际是 **1:134**,图上尺寸 ×0.745 才是模型值;
   - 根开扇形也是同因子压缩。
   **通用教训:任何图注比例/图面尺寸先交叉验证再用,单线图比例签是不可信的。**
3. **legs_fit.json 是错的**:拟合到了 ±18790 的尺寸界线上,不是腿线。→ 坐标来源必须人工看图确认每条线是什么,拟合程序不认识"尺寸界线"。
4. **标高标注(129571/114297/99152)是挂点标高,不是弦杆标高**;实际弦杆:L1 下弦 130880、L2 115832、L3 100558。
5. **008 下平面图比例签 1:30 是错的**(按它会大 2.4 倍);平面图只取比例关系(根:尖≈3.5:1),坐标仍用 001。
6. **共线聚类会过度合并**:平行相近的线(横杆/弦杆/其他视图的线)被并成一条;全局提取一定会漏角(第一版就因此丢了整个 L1 挂线头)。→ 关键区域必须局部重提取 + 节点图重建 + 渲染图人工比对。
7. **像素目测不可靠**:反复从渲染图上量尺寸,数字互相打架;最终全部改走 DXF 矢量提取。**能取矢量就别量像素。**
8. **变体平移的 z 坐标 bug**:延段斜材 lambda 里返回 z 忘了 −delta,出现负坐标;延段底宽必须取 `hw_v3(z0)` 与接腿顶连续,不能直接用根开表值。
9. ** DXF 版本**:用 ezdxf 1.4.4;转出来的 DXF 实体类型主要是 LWPOLYLINE 和 LINE,别的当不存在。
10. **001 上 L1 区有导线吊装施工孔 A/B**(下弦上,间距 2100),容易误读成挂点;①②⑤ 是件号不是节点号。

## 四、方法论沉淀(为什么这么做)

1. **单一权威 + 多重验证**:001 是唯一坐标来源;每个关键几何用三条独立信道验证(DXF 矢量提取 / 其他图纸尺寸换算 / 渲染图目视比对),三条都对才定稿。L1 的 W 形就是三条全对上(11405/16021/17140 ↔ 004 尺寸 ×0.745 ↔ 渲染轮廓)才收工。
2. **先建目录和层级,再动手建模**:126 张图先分类,知道去哪找数据,比边翻边建快得多。
3. **区分"几何"与"标注"是图纸解析的第一性问题**,靠图层+颜色规则化,不靠人眼每次判。
4. **粗略级 → 精细级分步走**:先轴线杆系(现在),后节点板/法兰级 BOM(待办)。每一步都有可交付的完整模型,而不是等全部细节。
5. **判据要"分类"不要"归零"**:碰撞检查、OCR 置信度、提取覆盖率,都要输出明细让人能审,一个漂亮的总分数字最会骗人。
6. **模型编号约定贯穿全链**:mid 前缀是颜色、规格、碰撞分组的唯一钥匙,加新部件先想好前缀。
